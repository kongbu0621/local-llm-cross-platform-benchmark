# Qwen3.8-27B / GX10 — 完整结果、稳定性与硬件验证详情（2026-09-03）

本页是 README 首页结果总表的完整分表。目标不是只给最终 `Decode tok/s`，而是把本轮已经真实取得的 **Formal5、Formal100、Effective Prefill、分位数/标准差、衍生指标、失败记录、Runtime/Hardware Gate、profiler 过程数据与结论边界** 都挂到同一条可核对证据链上。

> **重要语义：** 当前 Formal5 / Formal100 workload 是 **32,768 input + 256 output，Concurrency=1**。Formal100 主批次都在 **1 次 warmup 之后**运行，因此 canonical result 标记为 `cache_state=warm`、`comparison_mode=platform_optimized`、Evidence **B**、`coverage_status=partial_suite_metrics`。它不是仓库冻结 suite 的 cold-cache 完整 isolation 结果，也不是 `E2E@32K`（32,768 input + 32,768 output）。

指标统一解释见：[Benchmark 指标统一解释](../metrics/benchmark-metrics-glossary.md)。衍生收益/时间成本/相对提升见：[衍生数据与决策结论](qwen38-27b-gx10-derived-analysis-20260903.md)。

<a id="metric-guide"></a>
## 1. 指标逐项解释与公式

| 指标 | 含义 | 类型 | 趋势 | 本轮如何得到 | 不能误解为 |
| --- | --- | --- | --- | --- | --- |
| Effective Prefill* / Effective PP (tok/s) | 实际首 token 链路下的有效输入处理速度 | Derived | 越高越好 | `32768 / (TTFT_ms / 1000)` | Pure Prefill throughput |
| Pure Prefill / `pp_tps` | 只计算 prompt prefill 阶段本身的吞吐 | Unmeasured | 越高越好 | **本轮未单独测量** | 不允许拿 Effective Prefill* 改名 |
| TTFT (ms) | 请求发出到首个输出 token 到达 | Measured | 越低越好 | `vllm bench serve` | 纯 prefill kernel 时间 |
| TPOT (ms/token) | 首 token 后每个输出 token 的平均耗时 | Measured | 越低越好 | runner 直接测量 | 整个请求平均 token 时间 |
| Decode / TG (tok/s) | 首 token 后持续生成速度 | Derived | 越高越好 | `1000 / TPOT(ms)` | Output throughput |
| E2E (ms) | 请求发出到第 256 个输出 token 完整接收 | Measured | 越低越好 | runner 直接测量 | 正式 `E2E@32K` |
| ITL (ms) | 相邻输出 token 延迟 | Measured | 越低越好 | runner 直接测量 | TPOT 的完全等价物 |
| Std / P50-P99 | 批次离散与尾延迟 | Measured/statistical | 越低越稳 | runner 统计 | 24h 系统稳定性 |
| CV | `Std / Mean × 100%` | Derived | 越低越稳 | 本页派生 | 跨 workload 的绝对稳定性证明 |
| Peak output throughput | runner 峰值时间桶输出吞吐 | Measured/statistical | 越高越好 | `max_output_tokens_per_s` | **不是限速 cap** |

**Measured / Derived / Unmeasured 必须分开。** 本轮 Pure Prefill、32K-output E2E、目标长上下文 Peak Memory/KV、质量与 24h soak 均不能靠现有数字补出来。

### 4.5 稳定性结论

- **完成率：** 三种 Formal100 均 100/100，本轮 warm 32K+256 批次没有请求级 failure；
- **均值可重复性：** FP8 / NVFP4 的 Formal5→Formal100 主要均值漂移约在 ±0.5% 内；
- **尾延迟：** TTFT P99 相对 mean 高约 3.3%～4.0%，E2E P99 高约 2.7%～3.4%，没有数量级放大；
- **BF16：** 多轮阶段结果对运行状态更敏感，所以 Formal100 比单个 Formal5 更适合作为本轮 warm-batch 基线；
- **边界：** 以上只证明当前批次稳定性，不能外推成 32K 长输出、128K+ context、24h soak、重启恢复或语义质量稳定性。

<a id="conclusions"></a>
## 7. 本轮可以成立的结论

1. **性能：** 在 1×GX10、Qwen3.8-27B、32K+256、Concurrency=1、1 warmup 后主批次中，NVFP4 的 Effective Prefill*/TTFT/TPOT/Decode/E2E 综合最好，FP8 居中，BF16 最慢；
2. **稳定性：** 三档 Formal100 均 100/100；FP8/NVFP4 Formal5→Formal100 漂移小，Formal100 CV 约 1% 或更低；
3. **瓶颈正在迁移：** NVFP4 Decode 加速更大，因此 TTFT 在 E2E 中所占比例上升；未来继续优化 NVFP4 时，Prefill/TTFT 会越来越重要；
4. **BF16 状态敏感：** 多轮 Formal5 的阶段变化真实存在，但不能再用 `max_output_tokens_per_s` 的误读解释；
5. **Hardware Gate：** FP8 与 NVFP4 的 runtime/kernel/hardware 路径已经分别闭环；
6. **覆盖状态：** 本轮是 `platform_optimized` warm-batch 的部分 suite 数据，不是完整 cold-cache isolation；
7. **不能成立：** 没有 Pure Prefill、32K output、目标长上下文 memory/KV、质量、24h soak、多节点 scaling 实测，不能从当前数据外推。
